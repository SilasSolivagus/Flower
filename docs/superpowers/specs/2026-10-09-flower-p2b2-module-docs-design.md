# Flower P2-B2 设计：模块文档、影响声明与人工合入

日期：2026-10-09
上位文档：`docs/superpowers/specs/2026-09-28-flower-data-model-design.md`（§4.1 结构树、§5 文档、§6.4 双向链接）；P2-A 设计 `2026-10-08-flower-p2a-change-prd-design.md`；P2-B1 设计 `2026-10-09-flower-p2b1-links-design.md`。本文只写 P2-B2 的范围，以及在上位文档基础上补充或改变的决定。

## 1. 范围

- 模块文档：每个模块节点一份，按功能点分节。
- 影响声明：变更 PRD 声明影响哪些功能点，以及每个功能点的来源小节。
- 人工合入：变更 PRD 上线后，按功能点把内容合入模块文档，全部处理完时 PRD 变为「已合入」。
- 结构树：声明影响时可以当场新建模块与功能点。

不在 P2-B2 内：Agent 起草合入提案（P5）、知识库检索、结构树批量导入。

## 2. 用户已确认的决定（2026-10-09）

| 主题 | 决定 |
|---|---|
| 结构树怎么建 | 不要求先搭好。声明影响时可以当场新建模块和功能点；产品设置里的结构树页签照旧可以手动整理 |
| 合入方式 | 声明影响时为每个功能点指定 PRD 的来源小节（可多选、可不选）；合入页左侧是模块文档该功能点的现状，右侧预填来源小节内容，可编辑，逐个功能点「应用」或「跳过」 |
| 设计四节 | 模块文档、影响声明、合入、结构树与导航，按 2026-10-09 对话确认的内容 |
| 旧数据 | prd 系统没有模块文档，11 份页面都是变更 PRD 且没有层级（2026-10-09 只读核实），模块文档从零开始 |

## 3. 模块文档

- **对应关系**：`documents.kind = module`，`node_id` 指向结构树第二层节点（模块），每个模块最多一份（唯一约束：`node_id`，`kind = module` 且未删除）。编号沿用产品的文档编号（`PAN-PRD-n`）。
- **状态**：`active`（使用中）/ `archived`（已归档）。归档后只读，可以恢复为使用中。模块节点停用不影响文档状态。
- **正文**：单篇 markdown，与变更 PRD 相同的编辑器、自动保存、修订、对比、恢复、`[[ ]]` 链接、划词评论与整篇评论。结构约定：
  - 第一个二级标题之前为「概述」；
  - 每个功能点一个二级标题，标题文字为功能点名称；
  - 小节按功能点名称归一化（与评论锚点相同的规则：去掉编号与空白）定位。
- **与上位文档的差异**：上位文档 §5.2 写模块文档按小节存 `document_sections`。本设计改为单篇 markdown、按标题定位小节，理由是与 PRD 共用编辑器、修订、对比、链接与评论定位，不维护第二套存储。代价是有人手动改了小节标题后，该小节不再对应功能点；合入时找不到小节按「新增」处理，并在合入页提示。
- **功能点改名**：节点改名时，在同一事务内把对应模块文档里该小节的标题改成新名称，生成一条修订（摘要「功能点改名：旧名 → 新名」）。找不到小节时不改正文。
- **新建时机**：第一次往某个模块合入时，或在模块文档列表点开一个还没有文档的模块时，自动建出模块文档（概述为空）。也可以手动新建。
- **权限**：与变更 PRD 相同：产品编辑及以上可以修改；只读成员可以评论；只读 Token 不能写。

## 4. 影响声明

- 新表 `document_affected_nodes`（租户表，开 RLS）：`org_id`、`document_id`（变更 PRD）、`node_id`（功能点，结构树第三层）、`change_type`（added / modified / removed）、`source_sections`（jsonb：PRD 小节标题数组，可空）、`merge_status`（pending / applied / skipped）、`merged_revision_id`（可空）、`merged_by`、`merged_at`、`created_at`。唯一约束（document_id, node_id）。
- **编辑**：PRD 状态为草稿、评审中、已通过、已上线时，产品编辑及以上可以增删改声明；一旦有任何一条已应用或已跳过，声明锁定（只能在合入页处理）；作废与已合入的 PRD 声明只读。
- **当场新建节点**：选择器按名称搜索本产品的功能点；没有时可以在某个模块下新建功能点，或在某个业务域下新建模块再建功能点。新建走现有结构树服务（同名检查、事件记录不变）。
- **来源小节**：从 PRD 当前正文的小节列表中选（按 1–3 级标题，与修订对比相同的切分）。PRD 小节改名后，来源小节显示「已失效」，合入时该部分不预填。外部 PRD 没有正文，来源小节不可选。
- **事件**：`document.affected_nodes_changed`，payload 带 `changes`。

## 5. 合入

- **入口**：PRD 状态为「已上线」且有声明时，详情页显示「合入模块文档」，进入合入页。
- **合入页**：按模块分组，逐个功能点：
  - 左侧：模块文档中该功能点小节的当前内容（新增时为空；模块文档还不存在时为空并提示将自动新建）；
  - 右侧：可编辑的文本，预填来源小节内容（多个来源按声明顺序拼接；没有来源时为空）；`removed` 类型右侧为空，说明「应用后将删除该小节」；
  - 操作：「应用」或「跳过」。
- **应用**（一个功能点一个事务）：
  - 锁模块文档行（不存在则新建），按小节定位替换该功能点小节的正文；新增时按结构树中功能点的顺序插入到对应位置；删除时移除该小节；
  - 生成一条修订：摘要「合入 PAN-PRD-12：功能点名」，`merged_from_document_id` 为变更 PRD；与自动保存相同的版本号检查，模块文档有更新的版本时返回冲突，合入页提示刷新左侧后重试；
  - 更新声明行为 applied，记录修订 id；
  - 记录事件 `document.merged`（subject 为模块文档，payload 带变更 PRD、功能点、`changes`）。
- **跳过**：声明行为 skipped，记录事件。跳过后可以撤销为 pending 重新处理。
- **完成**：全部声明处理完（applied 或 skipped）时，在同一事务内把变更 PRD 状态改为 `merged`，记录事件；「PRD」检查项按现有映射（merged → 通过）同步。中途可以停下，下次接着做。
- **不能合入**：作废的 PRD；没有声明的 PRD（合入入口不显示，可以先补声明）。
- **权限**：产品编辑及以上；只读 Token 不能。
- **历史**：模块文档修订列表显示合入来源（链接到变更 PRD）。模块文档的「被引用」区块之外，另加「合入记录」区块：按时间列出来自哪些变更 PRD、哪些功能点。功能点的历史即这些记录中对应它的部分。

## 6. 结构树与导航

- 第二层、第三层的显示名称沿用产品设置里的层级叫法（缺省「模块」「功能点」）。
- 文档列表加「模块文档」页签：按业务域 → 模块列出，显示是否已有文档、最近合入时间；点击没有文档的模块即新建。
- `[[业务域/模块]]` 链接到该模块的模块文档；`[[业务域/模块/功能点]]` 链接到模块文档并滚动到该小节（沿用 P2-B1 的 `?section=`）。模块还没有文档时跳到「模块文档」页签并定位到该模块。
- 结构树页签中，模块节点显示其模块文档链接。

## 7. 验证

- 单元测试：
  - 模块文档唯一性与自动新建；
  - 声明的增删改与锁定；
  - 应用（替换、新增按顺序插入、删除）、修订与来源、版本冲突；
  - 全部处理完自动变为已合入，「PRD」检查项同步；
  - 功能点改名同步标题；
  - 跳过与撤销；
  - 权限（编辑、只读、只读 Token）。
- 端到端测试：
  - 声明影响时当场新建模块与功能点；
  - 合入页逐个应用与跳过，PRD 变为已合入；
  - 模块文档的修订来源与合入记录；
  - 节点链接跳到模块文档小节；
  - 1440 与 760 两种宽度。
- 真实数据：在 pan123 上，用一份测试用的已上线 PRD 走完声明 → 合入流程（不改迁移来的数据），1440 与 760 复验。
