# Flower P2-B1 设计：双链与反向链接

日期：2026-10-09
上位文档：`docs/superpowers/specs/2026-09-28-flower-data-model-design.md`（§4 需求与任务、§6.4 双向链接）；P2-A 设计 `docs/superpowers/specs/2026-10-08-flower-p2a-change-prd-design.md`。本文只写 P2-B1 的范围，以及在上位文档基础上补充或改变的决定。

## 1. 范围

P2-B 拆为两段：
- **P2-B1（本文）**：`[[双链]]`、反向链接、任务编号，以及 P2-A 留下的两项——编辑器内高亮评论锚点、PRD 的未读评论进工作台。
- **P2-B2**：模块文档、影响声明、人工合入，以及结构树补建模块与功能点。

不在 P2-B1 内：外部平台内容自动抓取、非图片附件、链接关系图谱、把系统关系写进链接表。

## 2. 用户已确认的决定（2026-10-09）

| 主题 | 决定 |
|---|---|
| 拆分 | P2-B1 / P2-B2，如上 |
| 输入 | 在 PRD 编辑器、需求描述、评论中输入 `[[` 弹出搜索补全，按编号或标题搜索，选中后插入；保存后显示为链接卡（编号、当前标题、状态） |
| 链接目标 | 需求、PRD、PRD 的小节、结构树节点、迭代、任务 |
| 迭代与任务的标识 | 任务按产品新增编号（`PAN-T-12`），现有任务按创建顺序补号；迭代用名称，同产品内迭代名称改为唯一 |
| 反向链接 | 需求、PRD、任务、迭代详情页各加「被引用」区块，只列手写的 `[[ ]]`；覆盖、迭代归属等系统关系不重复写入 |
| 旧数据 | 现有需求描述与评论中没有编号互引的写法（2026-10-09 只读核实），不回填 |

## 3. 语法

| 目标 | 写法 | 定位 |
|---|---|---|
| 需求 | `[[PAN-123]]` | 产品 key + 需求编号 |
| PRD | `[[PAN-PRD-12]]` | 产品 key + 文档编号 |
| PRD 小节 | `[[PAN-PRD-12#需求说明]]` | 文档 + 小节标题（与评论锚点相同的标题归一化：去掉编号与空白）；同名小节取第一个 |
| 任务 | `[[PAN-T-12]]` | 产品 key + 任务编号 |
| 迭代 | `[[迭代:名称]]`，跨产品写 `[[PAN/迭代:名称]]` | 产品 + 迭代名称 |
| 结构树节点 | `[[业务域/模块/功能点]]`，跨产品写 `[[PAN/业务域/…]]` | 产品 + 节点名称路径 |

其他约定：
- 可选显示文字：`[[PAN-123|登录改版]]`，显示文字只影响展示，不影响定位。
- 代码块与行内代码中的 `[[ ]]` 不解析；`\[[` 为转义。
- 编号大小写不敏感，保存时规范为大写。旧编号通过 `entity_aliases` 解析。
- 不带产品前缀的迭代与节点写法，按来源对象所在产品解析。

## 4. 数据模型

- 新表 `entity_links`（租户表，开 RLS）：
  - `org_id`；
  - `source_type`（requirement / document / comment）、`source_id`、`source_section`（PRD 小节标题，可空）；
  - `target_type`（requirement / document / task / iteration / structure_node，可空）、`target_id`（可空）、`target_section`（可空）；
  - `target_text`（原文，如 `PAN-PRD-12#需求说明`）、`context`（引用处所在的一句，截断到 120 字）；
  - `origin`：P2-B1 只写 `wikilink`，保留 system / manual 两个值给后续阶段；
  - `created_at`。
  - 索引：（source_type, source_id）、（target_type, target_id）、（org_id, target_text）。
- 写入时机：需求创建或改描述、PRD 保存正文（含合并修订、恢复、导入、转为 Flower 文档）、评论新建或修改。每次在同一事务内删除该来源的全部链接再重建。外部 PRD 没有正文，只有评论里的链接。
- 悬空链接：目标不存在时 `target_id` 为空。新建需求、PRD、任务、迭代、节点，以及改迭代名称、节点名称时，按 `target_text` 补上同组织内的悬空链接。
- 断链：链接存目标 id，目标改标题、改编号都不影响。目标被删除或取消时链接保留，显示为灰色；PRD 小节改名或删掉后，链接显示「小节已失效」。
- 任务编号：`tasks.number`，由 `products.task_seq` 以 `update … returning` 分配（与需求、文档编号相同做法）。新迁移按产品、创建时间顺序为现有任务补号，并把 `task_seq` 设为最大值。迁移工具导入任务时同样编号。
- 迭代名称唯一：（product_id, name）唯一约束；新建和改名重复时报「同一产品内已有同名迭代」。迁移前先只读核对，pan123 的 13 个迭代没有重名。

## 5. 权限

- 链接解析与写入随来源对象的写操作进行，权限沿用来源对象的规则。
- 显示链接卡时，看不到目标所在产品的人只看到编号，不显示标题与状态。
- 「被引用」区块只列出查看者能看到的来源。

## 6. 界面

- **补全**：输入 `[[` 后弹出搜索框。
  - 按编号前缀或标题关键词搜索需求、PRD、任务、迭代、节点；需求与 PRD 先显示本产品的结果。
  - 选中 PRD 后可以继续选它的小节。
  - 选中后插入规范写法。
  - 键盘操作：上下选择、回车插入、Esc 关闭。
- **链接卡**：链接显示为行内链接卡（编号、当前标题、状态），点击跳转；指向 PRD 小节时跳到详情页并滚动到该小节。目标不存在、已删除或小节失效时显示为灰色，并附说明。
- **需求描述与评论**：仍是纯文本输入框，加补全弹层；显示时把 `[[ ]]` 渲染为链接卡。
- **「被引用」区块**：需求、PRD、任务、迭代详情页各加一块，按来源分组。每条显示来源（需求描述 / 某份 PRD 的某个小节 / 某条评论所在的对象）、引用处的一句上下文和时间。
- **任务编号**：任务列表、任务详情、甘特、工作台显示 `PAN-T-12`。
- **评论锚点高亮**：PRD 编辑器中，有未解决评论的原文加底色；点击后右侧评论区滚动到该条并高亮。已失效、已解决的评论不高亮。
- **PRD 未读评论**：工作台「未读评论」加入 PRD 的评论。范围沿用需求的规则：我负责的，或我参与过评论的。打开 PRD 详情即标为已读。

## 7. 验证

- 单元测试：
  - 解析：各种语法、显示文字、代码块与行内代码、转义、大小写、跨产品前缀；
  - 定位：旧编号别名、PRD 小节归一化；
  - 悬空链接自动接上；
  - 任务编号分配与补号迁移。
- 端到端测试：
  - 三处输入框的 `[[` 补全；
  - 链接卡跳转（含小节滚动）；
  - 「被引用」区块；
  - 改编号或改标题后链接不断；
  - 小节改名后显示失效；
  - 无权限时只显示编号；
  - 评论锚点高亮与点击联动；
  - 工作台的 PRD 未读评论。
- 真实数据：在 pan123 上执行任务补号迁移，核对数量；1440px 与 760px 两种宽度复验。
