## 5. 人工验收清单（供用户在本地 pan123 上试用）

用自己的账号登录 `pnpm dev` 启动的开发环境，逐项打勾；发现的问题记在本节末尾。验收中新建的测试数据用「验收-」开头命名，结束后取消或删除。

说明：第 7 条「PRD 评审签字」需要先给本产品流程加一个**作用于 PRD（文档级）的会签检查项**，pan123 迁移来的流程里没有现成的这一项。

新建与编辑
- [ ] 在某条需求上新建一份 Flower 内 PRD，写正文（含至少一张图片），保存后刷新页面内容仍在。
- [ ] 用两个浏览器窗口打开同一份 PRD：窗口 A 改一处正文等待自动保存，窗口 B 不刷新也改一处正文保存，确认出现冲突提示而不是静默覆盖；按提示处理后两边最终一致。
- [ ] 打开该 PRD 的「修订」列表，选两个版本「对比」，确认按小节显示差异；选一个旧版本「恢复」，正文回到该版本内容并产生新修订。
- [ ] 在正文里选中一段文字添加评论；之后编辑掉这段文字，确认该评论标记「已失效」。

转换
- [ ] 新建一份外部 PRD（粘贴一个链接），用「转为 Flower 文档」的三种方式各试一次：粘贴正文、上传 Markdown 文件、上传 Word 文件，确认转换后内容进入 Flower 编辑器。

PRD 与需求联动
- [ ] 给一条需求挂一份 PRD 后，需求详情的「PRD」检查项变为跟随 PRD 状态、不能手改；PRD 状态变化后检查项随之更新。

评审与签字
- [ ] 给流程加一个作用于 PRD 的会签检查项，推进一份 PRD 到评审中状态；在评审页「PRD 评审」区块或工作台「等我签字」里完成一次签字；验收后把流程改回。

模板
- [ ] 文档模板设置「必填小节」生效：新建 PRD 时缺少必填小节，提交评审（draft → review）被拦截并提示缺少的小节名。

权限
- [ ] 用一个只读成员账号打开一份 PRD：可以添加评论，但正文、状态、模板、覆盖需求等均不可编辑；只读 Token 不能添加评论。
